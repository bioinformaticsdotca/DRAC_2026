Module 4. Submit and monitor jobs with Slurm

Why use a scheduler?

On HPC, computation is submitted as a job. Slurm reserves cores, memory and time, and executes the job on an allocated compute node rather than on the login node.

Write a batch script

Create hello.sbatch with nano hello.sbatch and enter:

#!/bin/bash
#SBATCH --job-name=hello-hpc
#SBATCH --account=def-sponsor00
#SBATCH --time=00:05:00
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=1
#SBATCH --mem=1000M

set -euo pipefail
printf 'Host: %s\n' "$(hostname)"
printf 'Job: %s\n' "$SLURM_JOB_ID"
printf 'CPUs: %s\n' "$SLURM_CPUS_PER_TASK"
sleep 10
printf 'Finished\n'

Submit and inspect:

sbatch hello.sbatch
sq
sacct --format=JobID,State,Elapsed,MaxRSS,ExitCode,NodeList
cat slurm_JOB_ID.out

Replace JOB_ID with the ID returned by sbatch. sacct reporting can lag and depends on the cluster’s accounting configuration.

Understand resource requests

Slurm Option Description Analogy (Restaurant)
--time Maximum wall-clock time for the job Time allowed to prepare an order
--ntasks Number of tasks/processes Number of dishes being prepared simultaneously in an order
--nodes Number of compute nodes Number of kitchens
--cpus-per-task Number of CPU cores per task Number of chefs working on each dish
--mem Memory allocated per node Available workspace in each kitchen

Request resources based on measured usage instead of reserving much more than necessary. A job may remain PENDING while resources are unavailable.

Monitor and diagnose jobs

sq
sacct --format=JobID,JobName,State,Elapsed,MaxRSS,ReqTRES%60
scancel JOB_ID                 # Only when you intend to cancel the job
seff JOB_ID                     # Display the utilization

If you see OUT_OF_MEMORY or a time-limit failure, inspect logs and resource requests before rerunning.

Interactive allocations

salloc

For short tests and troubleshooting, request an interactive allocation:

salloc --time=00:15:00 --cpus-per-task=1 --mem=1G
srun --pty bash
hostname
htop                     # Press "q" to quit
echo $SLURM_TMPDIR       # Display the path to local temporary storage
exit                     # Exit the compute-node shell
exit                     # Release the allocation

The first exit closes the interactive shell on the compute node. The second exit leaves the allocation shell and releases the Slurm allocation.

JupyterHub

Open the workshop JupyterHub in your browser and follow the organizer’s instructions.

A typical workflow is:

  1. Sign in with your workshop credentials.
  2. Select an available compute profile, if prompted.
  3. Launch a notebook or terminal.
  4. Shut down your session when finished.

Exercise

Submit a new job which runs the following command:

timeout 120s bash -c 'x=$(head -c 250M /dev/zero | tr "\0" x); sleep 120'

find its job ID, inspect its output log, and report whether the job completed successfully.
